# クオリティチェック（quality-check）購入者導入ガイド（完全版）

quality-check は、Web 制作の納品前品質チェックと修正対応を自動化する Claude Code 用スキルです。HTML/CSS/JS のコード検証、SEO・メタデータ、リンク切れ、デザインカンプ照合、テキスト誤字脱字、WordPress 固有チェックまでを一括で実行してレポートを出力します。さらに、クライアントからの修正指示（CSV・テキスト・画像）を読み取ってコードに反映する「修正モード」も備えています。本ガイドは、購入〜契約〜セットアップ〜日常利用〜サポート窓口〜トラブル対応までを解説する購入者向けの完全版マニュアルです。

対象読者: quality-check を購入（またはAIクラフトラボ会員特典として利用開始）する方。

## 1. サービス概要とプラン

quality-check は、AIクラフトラボ会員特典として、または月額サブスクリプション契約でご利用いただけます。**1つのライセンスキーで、当社が提供する対応スキル（static-code / wireframe / pre-check / quality-check など）を横断してご利用いただけます**（スキルごとにキーを分ける必要はありません）。

- チェックの工程手順・照合ロジック・修正手順・レポート様式などの詳細はローカルには保存されず、実行のたびに skill API サーバー（Google Cloud Run）から取得してその場で利用する方式です。手元に残るのは通信用のクライアントコードと、チェック項目のファイル（`check-items.md`）のみです。
- そのため、**利用にはインターネット接続とライセンスキーが必須**です。
- ライセンスは「1 ライセンスキー = 1 契約者・1 マシン」の制約です。
- 既に static-code など他スキルのライセンスキーをお持ちの場合、**同じキーをそのまま quality-check でも利用できます**（キーの再設定は不要。「4. セットアップ手順」のクライアント配置のみ行ってください）。

## 2. 購入〜契約の流れ

### ①AIクラフトラボ会員の場合

1. AIクラフトラボへの入会手続きを完了する（通常のラボ受講申込フロー）
2. ラボ運営（まさた）より、ライセンスキー（`SL-XXXX-XXXX-XXXX` 形式）が発行・案内される（他スキルで発行済みのキーがあればそれを使えます）
3. 本ガイドの「4. セットアップ手順」に進む

### ②月額サブスクリプションの場合

1. 申込ページからStripe決済を行う（クレジットカード決済、無料トライアルなし）
2. 決済完了後、登録したメールアドレス宛てにライセンスキー（`SL-XXXX-XXXX-XXXX`）が届く
   - 届かない場合は購入時のメールアドレスの入力ミス、または迷惑メールフォルダを確認する。それでも見当たらない場合は「7. サポート窓口」へ連絡
3. 契約は毎月自動更新（次回請求日の前に解約手続きを行わない限り継続課金）
4. 解約したい場合は次回請求日より前に手続きする（手続き方法は購入時の案内・Stripeカスタマーポータルを参照。詳細不明な場合はサポート窓口へ）
5. 本ガイドの「4. セットアップ手順」に進む

## 3. 前提環境

- Claude Code がインストール済みであること
- Python 3（標準ライブラリのみで動作します。追加の pip インストールは不要です）
- デザインカンプ照合で Figma を使う場合: Figma MCP が Claude Code に設定済みであること（未設定でもカンプ画像での照合、および照合なしのチェックは可能です）
- **Claude Code 自体の利用契約（Claude Pro / Max または Claude API）は購入者ご自身で別途契約する必要があります。** 本サービスにはClaude Code自体の利用権は含まれません（当社はClaudeへのアクセスを代理提供・再販しません）

## 4. セットアップ手順

### 4-1. ライセンスキーを設定する

購入・入会時に受け取ったキーを以下のコマンドで設定します。**他スキル（static-code 等）で既に設定済みの場合、この手順は不要です**（同じ場所・同じキーを共用します）。

```bash
mkdir -p ~/.config/skill-license
echo 'SL-XXXX-XXXX-XXXX' > ~/.config/skill-license/license
```

`SL-XXXX-XXXX-XXXX` の部分は実際に受け取ったキーに置き換えてください。マシン識別用の `machine_id` は初回実行時に自動生成され、同じく `~/.config/skill-license/` に保存されます（自分で作成・編集する必要はありません）。

> 補足: 設定先フォルダ名が `static-code` なのは、対応スキル共通のライセンス保管場所として使っているためです。quality-check 専用に別フォルダを作る必要はありません。

### 4-2. クライアントスキルを配置する

配布された `quality-check.zip` を展開すると、`quality-check` というフォルダができ、次の構成になっています。

```
quality-check/                   （このフォルダごとスキルディレクトリへ置く）
├── SKILL.md
├── references/
│   └── check-items.md
├── client/
│   └── sc_client.py
└── README_FIRST.md              （このガイド。スキルの動作には不要なので、不要なら削除して構いません）
```

**展開してできた `quality-check` フォルダを、そのまま Claude Code のスキルディレクトリ（`~/.claude/skills/`）の中に入れるだけ**です。Finder なら `~/.claude/skills/` の中へドラッグ＆ドロップ、コマンドなら次のとおりです。

```bash
# quality-check.zip を展開したフォルダがある場所で実行
cp -R quality-check ~/.claude/skills/
```

配置後は `~/.claude/skills/quality-check/` に SKILL.md・references・client が入っていれば完了です（`README_FIRST.md` は残っていても動作に影響しません。不要なら削除して構いません）。

### 4-3. 権限（settings）の許可について

このスキルは `SKILL.md` の `allowed-tools` に、Bash（`python3` 実行のため）や Read/Write/Edit などを含んでいます。初回に `python3 client/sc_client.py ...` を実行する際、Claude Code から Bash 実行の許可を求められることがあります。その場合は許可してください。

毎回の確認を減らしたい場合は、Claude Code の設定（settings）で `python3` コマンドをあらかじめ許可（allowlist）しておくことができます。設定方法が分からない場合は Claude Code 側で「python3 コマンドを許可して」のように依頼してください。

### 4-4. セットアップ完了の確認

セットアップ後、Claude Code で「品質チェックして」等と依頼してみて、エラーなくセッションが開始されればセットアップ完了です。エラーが出た場合は「8. トラブルシューティング」を参照してください。

## 5. 使い方（チェックモード / 修正モード）

セットアップが終われば、通常どおりスキルを呼び出すだけです。

### チェックモード（納品前の一括チェック）

- 対象パス（＋任意で Figma URL やカンプ画像）を渡して「品質チェックして」「納品前チェック」「QCして」のように依頼します。
- スキルが自動的にセッションを開始し、工程手順をサーバーから取得しながら、コード検証 → SEO/メタデータ → リンク/リソース → デザイン照合 → テキスト → WordPress固有 → レポート生成、の順で進めます。
- 生成物は品質チェックレポート（エラー/警告/情報の一覧＋手動チェックリスト）で、案件フォルダの `Generated/` に保存されます。

### 修正モード（修正指示の反映）

- 「修正指示を反映して」「修正対応して」と依頼し、クライアントからの修正指示ファイル（CSV/テキスト/画像）を渡します。
- 指示を一覧化 → **修正計画を提示（承認）** → 承認後に1件ずつ修正実行 → 対応結果を報告、という流れで進みます。**ユーザーの承認なしにコードは変更されません**。

## 6. チェック項目（check-items）のカスタマイズ

quality-check に同梱される `references/check-items.md` は、チェック項目の一覧です。**ご自身で編集・追加していただけます**。自社で必ず確認する項目（独自のコーディング規約・SEO基準など）を追記しておくと、次回以降のチェックに反映されます。

- 追記の際は、既存項目の記法（Phase・項目番号・重要度の付け方）に合わせてください。レポートの一貫性が保たれます。
- `check-items.md` はローカルのファイルなので、編集内容はそのマシンでのチェックに即反映されます（サーバーへの再取得は不要です）。
- チェックの工程手順・照合ロジック・修正手順・レポート様式はサーバー側にあり、随時改善されて全ユーザーに自動反映されます。

## 7. サポート窓口

- 問い合わせ窓口: Discord の DM（まさた宛て）でご連絡ください
- 問い合わせ時にご記載いただきたい情報:
  - ライセンスキー（`SL-XXXX-XXXX-XXXX`）

## 8. トラブルシューティング

| 事象 | 意味 | 対処 |
|---|---|---|
| セッション開始で `409` | 別のマシンで利用中（同一ライセンスキーが他マシンでセッション中） | 前のマシンでの作業終了から 60 分待って再試行してください |
| セッション開始で `403` | このライセンスキーは既に別のマシンに登録済み | PC を買い替えた等の理由がある場合は machine reset が必要です。サポート窓口（Discord の DM）に連絡してください |
| セッション開始で `401` | ライセンスキーが無効（未登録・入力ミス・失効済み） | キーの入力内容（`~/.config/skill-license/license`）を確認してください。解決しない場合はサポート窓口に連絡してください |
| 「ライセンスキー未設定」 | `~/.config/skill-license/license` が存在しない、または空 | 「4-1. ライセンスキーを設定する」を再実行してください |
| 工程取得で応答がない・APIに接続できない | ネットワーク不通または API 側の一時的な障害 | ネットワークを確認のうえ、時間をおいて再試行してください。復旧状況はサポート窓口・ステータス通知先を確認してください |
| デザインカンプ照合が動かない | Figma MCP が未設定、または閲覧権限のないURL | Figma MCP の設定と、URLの共有権限を確認してください。カンプ画像での照合、または照合なしのチェックに切り替えることもできます |
| 決済したのにライセンスキーが届かない | メールアドレス入力ミス、迷惑メールフォルダ、配信遅延 | 迷惑メールフォルダを確認のうえ、届かない場合はサポート窓口に決済完了の証跡（Stripe領収書等）と併せて連絡してください |

## 9. 障害時の考え方

quality-check は個人開発規模のサービスであり、SLA（稼働率保証）は設けていません。ベストエフォートでの運用です。詳細な取り扱い（24時間超障害時のサブスク日割り延長、ステータス通知方法等）は `docs/法務/障害時ポリシー_ドラフト.md` を参照してください。

要点のみ再掲します。

- チェック・修正の工程手順は実行のたびにサーバーから取得するため、API障害中は新規のチェック/修正を開始できません（復旧後に実行してください）。
- 既に生成済みのレポートや、既に反映済みの修正は手元に残っているため、その活用・編集はローカルで継続できます。
- 24時間を超える障害が発生した場合、サブスクリプション契約者には日割りでの延長対応を行います。
