# チェック項目詳細

SKILL.md の Step 1〜6 で参照する。各Phaseに入る前にこのファイルの該当セクションをReadして、項目に沿ってチェックを実行する。

---

## Phase 1: コード検証

HTML/CSS/JSファイルを読み込み、構文・構造の問題を検出する。

| # | チェック項目 | 検出方法 | 重要度目安 |
|---|---|---|---|
| 1-1 | 閉じタグの欠落・不一致 | HTMLファイルを読み、開きタグと閉じタグの対応を確認 | エラー |
| 1-2 | W3C準拠（主要なHTML/CSSエラー） | 無効な属性、入れ子ルール違反（例: `<p>` 内に `<div>`）を検出 | エラー |
| 1-3 | 不要コメントの残存 | `<!-- TODO -->`, `<!-- test -->`, `/* debug */` 等の開発用コメント | 警告 |
| 1-4 | `console.log` / デバッグコードの残存 | JSファイル内の `console.log`, `console.debug`, `debugger` | エラー |
| 1-5 | コンソールエラーにつながる記述 | 未定義変数の参照、存在しないDOM要素へのアクセス、構文エラー | エラー |
| 1-6 | ID重複 | 同一HTMLファイル内で同じid属性が複数存在 | エラー |
| 1-7 | 空リンク・無効リンク | `href="#"` のみの `<a>` タグ、`href` 属性がない `<a>` タグ | 警告 |
| 1-8 | 非推奨タグ・属性 | `<font>`, `<center>`, `<marquee>`, `align` 属性, `bgcolor` 属性 | 警告 |
| 1-9 | z-indexの異常値 | `z-index: 9999` 等の極端な値。意図的な場合もあるため警告扱い | 警告 |

## Phase 2: SEO・メタデータ検証

`<head>` 内のメタ情報と見出し構造を検証する。

| # | チェック項目 | 判定基準 | 重要度目安 |
|---|---|---|---|
| 2-1 | `<title>` タグ | 存在するか。文字数が30〜60字の範囲か | エラー（なし）/ 警告（文字数） |
| 2-2 | `<meta name="description">` | 存在するか。文字数が80〜160字の範囲か | エラー（なし）/ 警告（文字数） |
| 2-3 | `<meta name="keywords">` | 設定されているか | 情報 |
| 2-4 | H1タグ | 存在するか。1ページに1つだけか | エラー（0個）/ 警告（2個以上） |
| 2-5 | 見出し階層の整合性 | H1→H2→H3の順序。H2を飛ばしてH3がないか | 警告 |
| 2-6 | OGPタグ一式 | `og:title`, `og:description`, `og:image`, `og:url` が揃っているか | エラー（主要タグなし）/ 警告（一部欠落） |
| 2-7 | 画像alt属性 | 装飾画像以外の `<img>` に空でないalt属性があるか | 警告 |
| 2-8 | ファビコン | `<link rel="icon">` または `<link rel="shortcut icon">` の記述があるか | 警告 |
| 2-9 | 解析タグ | GA4（`gtag.js` or `G-`）/ GTM（`gtm.js` or `GTM-`）のスクリプトが記述されているか | 警告 |
| 2-10 | viewport設定 | `<meta name="viewport" content="width=device-width, initial-scale=1">` があるか | エラー |
| 2-11 | 言語属性 | `<html lang="ja">` が設定されているか | 警告 |
| 2-12 | canonical URL | `<link rel="canonical">` が設定されているか | 情報 |
| 2-13 | 構造化データ | `<script type="application/ld+json">` の記述があるか | 情報 |
| 2-14 | noindex/nofollow | `<meta name="robots" content="noindex">` の状態。本番では外れているべき、テスト環境では付いているべき | エラー（本番でnoindexが残っている場合） |

## Phase 3: リンク・リソース検証

リンク先・画像・CSS/JSのパスがファイルシステム上に実在するかを確認する。

| # | チェック項目 | 検出方法 | 重要度目安 |
|---|---|---|---|
| 3-1 | 内部リンクのパス実在確認 | `<a href="...">` のパスを抽出し、対象ディレクトリ内にファイルが存在するか確認。外部URL（http/https始まり）は対象外 | エラー |
| 3-2 | リンクのクリック範囲 | `<a>` タグの中身がテキストだけか、ブロック要素を含むか。カード型UIでクリック範囲が狭すぎないか | 情報 |
| 3-3 | 画像ファイルの存在確認 | `<img src="...">`, `background-image: url(...)` のパスにファイルが存在するか | エラー |
| 3-4 | CSS/JSファイルのパス確認 | `<link href="...">`, `<script src="...">` のパスにファイルが存在するか | エラー |
| 3-5 | 外部リンクのセキュリティ属性 | `target="_blank"` がある `<a>` タグに `rel="noopener noreferrer"` が付いているか | 警告 |
| 3-6 | 画像ファイルサイズ | 対象ディレクトリ内の画像ファイルで500KB以上のものを検出 | 警告 |
| 3-7 | 次世代画像フォーマット | jpg/png のみで WebP/AVIF が使われていない場合に情報として出力 | 情報 |
| 3-8 | フォント読み込みパス | Google Fonts等の外部フォントリンク、またはローカルフォントファイルのパスが正しいか | 警告 |

## Phase 4: デザインカンプ照合（Figma MCP / カンプ画像）

Figma URLが指定された場合のみ実行する。`figma-remote-mcp` の `get_design_context` でデザインデータを取得し、コード側のHTMLテキスト・CSSプロパティと突き合わせる。

ページ単位で実行する。対象ページが複数ある場合は1ページずつ順に照合する。

| # | チェック項目 | 検出方法 | 重要度目安 |
|---|---|---|---|
| 4-1 | テキスト内容の一致 | Figma上のテキストノードとHTML内のテキストを比較。漢字1文字の違いも検出する | エラー |
| 4-2 | フォントサイズの一致 | Figmaのフォントサイズ指定とCSSの `font-size` を比較 | 警告 |
| 4-3 | フォントファミリーの一致 | Figmaのフォント指定とCSSの `font-family` を比較 | 警告 |
| 4-4 | カラーコードの一致 | Figmaのカラー値とCSSの `color`, `background-color` を比較 | 警告 |
| 4-5 | 要素の表示/非表示の不一致 | Figma上に存在する要素がHTML上にない、またはその逆 | エラー |
| 4-6 | ダミー画像の残存 | placeholder画像、仮画像がそのまま残っていないか | エラー |
| 4-7 | ダミーテキストの残存 | 「テキストが入ります」「サンプルテキスト」「Lorem ipsum」等 | エラー |

## Phase 5: テキスト・コンテンツ検証

HTMLの表示テキスト（タグ内のテキストノード）を抽出し、内容の正確性を検証する。

| # | チェック項目 | 検出方法 | 重��度目安 |
|---|---|---|---|
| 5-1 | 誤字脱字 | テキストを読み、漢字変換ミス・送り仮名の間違い・明らかな脱字を検出 | エラー |
| 5-2 | 郵便番号と住所の整合性 | `〒XXX-XXXX` の郵便番号と隣接する住所テキストが一致するか。日本の郵便番号の知識に基づいて判定 | エラー |
| 5-3 | 電話番号のフォーマット・桁数 | 電話番号が正しい桁数か（固定10桁、携帯11桁）。ハイフン位置は適切か | 警告 |
| 5-4 | placeholder残存 | 「テキストが入ります」「サンプル」「Lorem ipsum」「ダミー」「仮テキスト」等の文字列 | エラー |
| 5-5 | 著作権年号 | `©` や `Copyright` に続く年号が現在の年（または妥当な範囲）か | 警告 |
| 5-6 | 会社名・サービス名の表記統一 | ページ内で同一の会社名・サービス名が異なる表記（半角/全角、略称/正式名称）で混在していないか | 警告 |
| 5-7 | メールアドレスのフォーマット | `mailto:` リンクのアドレスが正しい形式か。`@` の前後が妥当か | 警告 |
| 5-8 | 日付フォーマットの統一 | ページ内で「2026年4月」と「2026/04」等、日付の書式が混在していないか | 情報 |

## Phase 6: WordPress固有チェック

対象ディレクトリにWordPress構成ファイル（`wp-config.php`, テーマ内の `functions.php` 等）がある場合のみ実行する。

| # | チェック項目 | 検出方法 | 重要度目安 |
|---|---|---|---|
| 6-1 | 404ページの存在 | テーマディレクトリ内に `404.php` があるか | エラー |
| 6-2 | テスト投稿の残存 | 「Hello World」「サンプルページ」等のデフォルトコンテンツがファイル内に残っていないか | 警告 |
| 6-3 | 不要プラグインの残存 | `wp-content/plugins/` 内に明らかに不要なプラグインディレクトリがないか（akismet等のデフォルト含む） | 情報 |
| 6-4 | ページネーション構造 | アーカイブテンプレートに `the_posts_pagination()` や `paginate_links()` 等のページネーション関数があるか | 警告 |
| 6-5 | ログインURL変更 | SiteGuard WP Plugin等のセキュリティプラグインが `wp-content/plugins/` に存在するか | 警告 |
| 6-6 | パスワード複雑性 | `wp-config.php` 内のDB_PASSWORDが単純でないか（短すぎ、辞書語等）を注意喚起 | 警告 |
| 6-7 | インデックス設定 | `<meta name="robots" content="noindex">` がテンプレートにハードコードされていないか（WP管理画面の設定とは別にコード上で確認） | エラー |
| 6-8 | バックアッププラグイン | `wp-content/plugins/` 内にUpdraftPlus等のバックアッププラグインが存在するか | 情報 |
